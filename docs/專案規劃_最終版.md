## 2. 深度與標籤策略

| 深度帶 | 標籤 | 來源 | 驗證方式 |
|---|---|---|---|
| 0–50 m | L1 七類：回填 / 黏土-粉土 / 砂 / 礫 / 互層 / 軟岩 / 硬岩 | 工程鑽孔 | 空間 block CV、獨立 hold-out |
| 50–300 m | L1（稀少類合併） | 工程深孔 + 水文地質鑽井（19 口 175–300 m） | 空間 CV + 外部井 leave-one-well-out |
| 300 m–1 km | **三粗類**：未固結沉積 · 軟岩 · 基盤 | 53 深孔、TEC 速度模型約束、文獻基盤面（北港基盤）、地調所 3D 模型成果報告 | 與文獻基盤面比較；圖上標示**外推/低信心** |

保底產品：基盤面深度圖 + 沉積/基盤二分類 + 信心圖。

## 3. 技術架構

```
tages-project/
  data/raw/{hydro, geoCloud, dem, tec_velocity, waveforms}
  data/interim/        # manifest、OCR 結果、清洗表
  data/processed/      # 特徵 parquet、Zarr 3D 體
  scripts/             # 可獨立執行腳本（fetch_*, build_*, train_*, infer_*）
  src/tages/{geo, labels, features, models, seismic, viz}
  configs/*.yaml  tests/  docs/  runs/  logs/
```
- 設定驅動：`--config xxx.yaml --device cpu|cuda`；每支腳本有 `--smoke`。
- 斷點續跑：`done.jsonl`；5090 任務有 `--max-minutes`。
- 座標：計算用 TWD97/TM2（EPSG:3826），儲存另附 WGS84；深度同時存 `depth_m` 與 `z_msl`。
- 實驗記錄：`runs/<date>_<commit>/`（config、指標、模型）。

### 5090 視窗標準流程（8 h）
1. 插硬碟、`git pull`、`check_env.bat`（CUDA 12.8+、PyTorch cu128 驗證）
2. `run_on_5090.bat --task <ocr|train|infer|ssr> --config ... --max-minutes 450`
3. 結果寫入 `outputs\<日期>_<task>\` + `status.md`；帶回本機
4. 每視窗只跑一種任務；5090 不做除錯；新程式必先本機 `--smoke` 通過

## 6. 成功判準
1. 驗證集：深度與岩性大類欄位準確率 ≥ 90%
2. 0–300 m：空間 block CV 與獨立 hold-out 的 macro F1 > 規則基準線；每類 recall 完整報告
3. 洩漏測試自動化通過；leave-one-well-out（水文地質井）報告
4. 3D 體可任意剖面，附信心/外推標示；基盤面與文獻比較
5. 一鍵重現與 README

## 7. 風險
| 風險 | 對策 |
